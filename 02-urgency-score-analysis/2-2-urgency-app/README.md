# 채용 적극성 분석기 (Streamlit)

채용공고 URL을 붙여넣으면 **채용 적극성**(접수 기간·모집 규모·즉시 입사 요구 등을
묶은 1~5점 지표)을 규칙과 모델이 각각 채점해 나란히 보여준다.

```bash
streamlit run app.py
```

지원 사이트: 잡코리아 · 사람인 · 원티드
(모델이 이 세 곳의 데이터로만 학습돼 있어서, 다른 사이트는 근거가 없다)

---

## 화면 설계에서 지킨 원칙

**규칙이 주 결과, 모델은 두 번째 의견.**

라벨 `urgency_score`는 규칙이 본문에서 정규식으로 만든 결정론적 값이다.
`라벨 = f(본문)` 이므로 **규칙이 계산 가능한 공고에서 모델은 정의상 규칙의
근사치**다. 모델을 앞에 세우면 근사치를 정답처럼 보이게 만든다.

그래서 규칙 점수를 크게 놓고, 모델은 옆에 대조용으로 둔다.
둘이 갈리면 **갈렸다고 그대로 보여준다.** 평균 내거나 합치지 않는다.

같은 이유로 화면에 반드시 남긴 것들:

| 표시 | 왜 |
|---|---|
| `in_scope=False` 경고 | 메타데이터 없는 공고에서 모델은 검증된 적이 없다 |
| "규칙이 실제로 읽은 텍스트" 펼치기 | 스크래핑이 깨졌을 때 사용자가 알아챌 수 있는 유일한 통로 |
| 조립된 헤더를 숨기지 않음 | 무엇을 근거로 채점됐는지가 점수보다 중요하다 |
| 진단 메시지 | 못 찾은 것을 못 찾았다고 말한다 |

## URL을 읽는 방법

사이트에서 긁은 HTML을 **그대로 쓰지 않는다.** 학습 데이터의 `raw_text`와
모양이 다르기 때문이다.

### 0. 바이트를 글자로 — 서버가 선언한 charset을 믿는다

`_get()`이 응답을 디코딩할 때 **서버 헤더의 charset을 우선**하고, 추측
(`apparent_encoding`)은 선언이 없을 때만 쓴다. 전에는 반대였다.

```python
r.encoding = r.apparent_encoding or r.encoding   # (구) 추측이 선언을 덮어씀
r.encoding = r.encoding or r.apparent_encoding   # (현)
```

추측을 앞에 두면 **본문에 UTF-8로 디코딩되지 않는 바이트가 하나만 섞여도**
`charset_normalizer`가 utf-8을 버리고 다른 인코딩(cp775 등)을 골라 페이지의
한글이 통째로 깨진다.

| 본문 | 추측 결과 | `모집인원 3명` |
|---|---|---|
| 정상 UTF-8 | `utf_8` | 그대로 |
| UTF-8 + 잘못된 바이트 1개 | `cp775` | `ļ¬©ņ¦æņØĖņøÉ 3ļ¬ģ` |

공고 본문은 워드·HWP에서 복사해 붙이는 자리라 이런 바이트가 섞인다. 세 사이트
모두 charset을 제대로 선언하므로(전부 `charset=utf-8`) 평소에는 추측도 맞고,
**가끔 한 건이 통째로 터진다.** 그게 제일 나쁘다 — 예외가 나지 않으니 규칙이
접수기간·모집인원을 못 찾고 조용히 폴백 점수가 나간다.

선언을 우선하면 피해가 **문서 전체에서 문제의 그 한 글자**로 줄어든다.

> 이 줄은 원래 필요한 우회였다. 예전 requests는 charset 없는 `text/*` 응답에
> `ISO-8859-1`을 기본값으로 넣어서 한글이 무조건 깨졌다. requests 2.32부터
> 그 기본값이 없어져 `None`을 돌려주므로, 위의 `or` 폴백이 그 자리를 대신한다.

### 1. 사이트별 수집 경로

| 사이트 | 문제 | 해법 |
|---|---|---|
| jobkorea | `남은기간`을 JS로 그려서 정적 HTML에 없음 | 렌더된 `시작일/마감일` 블록 파싱 → 실패 시 `<meta description>` 폴백 |
| saramin | 데스크톱 페이지에 **시작일이 없음**, 본문은 별도 엔드포인트 | 시작일은 **모바일 페이지**(`m.saramin.co.kr`), 본문은 `view-detail` |
| wanted | 마감일·모집인원이 구조적으로 없음 | 본문 하단 `마감일`만 파싱, 나머지는 측정 불가로 표시 |

사람인 모바일 페이지를 쓰는 이유가 중요하다. 데스크톱에는 마감일만 있어서
**접수 창 길이를 계산할 수 없고**, 그러면 사람인 공고는 마감 신호가 항상 0점이
된다. 모바일에는 `시작일 2026.08.31(월) 00:00 마감일 2026.09.07(월) 23:59`이
그대로 렌더돼 있다.

### 2. 사이트 크롬 제거 — 빼먹으면 점수가 통째로 밀린다

학습 데이터의 `raw_text`에는 사이트 전역 내비게이션이 없다
(jobkorea는 회사명부터, wanted는 직무기술서만 담겨 있었다).
긁은 평문을 그대로 쓰면 메뉴 텍스트가 공고 신호로 오인된다.

실제로 확인된 오탐:

```
잡코리아 GNB:  회원가입/로그인 기업 서비스 JOB 찾기 합격축하금 공채정보 …
                                          ^^^^^^^^
```

`합격축하금`이 '보상 유인' 신호로 잡혀 **+12점**이 붙었다. 모든 잡코리아
공고에 똑같이 붙으므로 점수가 전부 한 등급씩 밀린다. 개발 중 실측으로 잡아
`_strip_chrome()`으로 제거했다.

### 3. 정규 형식으로 재조립

뽑은 구조화 필드를 **학습 데이터와 같은 형식으로 다시 쓴다.**

```
접수기간 · 방법 시작일 2026.09.02 마감일 2026.09.10 모집인원 3 명  + 본문
```

이 형식이어야 `urgency_rule.RX_START_END`가 접수 창 길이를 계산한다.
조립 결과는 앱의 "규칙이 실제로 읽은 텍스트 보기"에서 전부 확인할 수 있다.

> ⚠️ **재현이지 동일이 아니다.** 크롤링 스냅샷과 100% 같은 문자열은 아니고,
> 사이트가 마크업을 바꾸면 조용히 어긋난다. 그래서 조립 결과를 숨기지 않는다.

## 점수에 넣지 않은 것 — 남은 일수(D-day)

앱은 `D-6` 같은 남은 일수를 **표시**하지만 **점수에는 넣지 않는다.**

남은 일수는 공고의 속성이 아니라 *내가 언제 봤는가*의 속성이다. 점수에 넣으면
어제 4점이던 공고가 오늘 5점이 된다. 대신 조회 시점과 무관한
**접수 창 길이**(마감일 − 시작일)를 쓴다.

이게 v2 라벨의 가장 큰 결함이었다 — 자세한 내용은
[`../urgency_rule.py`](../urgency_rule.py) 상단 주석 참조.

## 알려진 실패 모드

| 상황 | 앱의 동작 |
|---|---|
| **이미지 공고** (본문 전체가 이미지 한 장) | 본문 300자 미만이면 경고. OCR은 넣지 않았다 |
| **시작일 없음** (사람인 상시채용 등) | "창 길이를 못 쟀다"고 명시 — '창이 길어서 0점'과 구분해서 표시 |
| **마감된 공고** | 마감됨 뱃지 표시 |
| **메타데이터 없음** (주로 원티드) | 어휘 폴백으로 채점하되, 그게 미검증 방식임을 함께 표시 |
| **사이트 개편** | 정규식 기반이라 셀렉터보다는 버티지만 결국 깨진다. 진단 + 원문 노출로 알아챌 수 있게 함 |
| **지원하지 않는 사이트** | 거부하고 이유를 설명 (다른 사이트는 검증된 적이 없다) |

스크래핑이 아예 막히면 **본문 직접 붙여넣기** 모드로 우회할 수 있다.
단, 접수기간·모집인원 문구까지 함께 복사해야 규칙이 채점한다.

## 파일

```
2-2-urgency-app/
├── app.py                    Streamlit 앱 (분석 / 어떻게 만들었나 / 한계와 개선점)
├── scraper.py                URL -> 학습 데이터 형식의 raw_text
├── build_reference_stats.py  아래 분포 파일을 만드는 스크립트
├── reference_stats.json      데이터셋 분포 (점수의 상대 위치 표시용, 사전 계산)
├── requirements.txt
└── .streamlit/config.toml    1번 프로젝트와 동일 팔레트
```

의존 모듈 (상위 디렉터리 공유):
- [`../urgency_rule.py`](../urgency_rule.py) — 라벨 규칙 v5
- [`../urgency_model.py`](../urgency_model.py) — 모델 추론 인터페이스
  (`models_v5/` 우선, 없으면 `models_v4/` → `models_v3/`)

모델(`../2-1-urgency-prediction-model/models_v5/`)이 없어도 앱은 동작한다.
규칙만으로 채점하고 모델 칸에 사유를 표시한다.

규칙과 모델의 라벨 버전이 어긋나면(`RULE_VERSION` vs `MODEL.meta['rule_version']`)
앱이 "한계와 개선점" 탭에 경고를 띄운다. 규칙은 코드라 즉시 바뀌고 모델은 재학습
시점에 고정되므로, 어느 쪽을 보고 있는지 화면에서 말해준다.

**`reference_stats.json`은 이 검사에 포함돼 있지 않다.** 버전이 어긋나도 앱은
아무 말 없이 옛 분포로 백분위를 계산한다.

> ⚠️ 그래서 **라벨을 다시 만들면 `python build_reference_stats.py --write`도
> 반드시 함께 돌린다.** 손으로 고치지 말 것. 전에 이 파일만 생성 스크립트 없이
> 놓여 있어서, 라벨이 v4가 된 뒤에도 v3 분포인 채 남아 앱이 조용히 틀린
> 백분위를 보여줬다. v5 라운드에서도 이 파일을 함께 갱신했다.

## 네트워크 예의

사용자가 붙여넣은 공고 **1건**을 조회하는 용도다. 목록 크롤링이나 대량 수집은
하지 않는다. 같은 URL은 10분간 캐시한다(`@st.cache_data(ttl=600)`).
